# 房产带看与佣金归属工作台

内部作业系统：登记房源、客户、带看经纪人、预约时间与带看签到；客户在保护期内成交时，
系统按**已签署并冻结版本的团队规则**给出佣金归属候选，并保留每次带看的证据
（签到时间、客户手写签字图、客户短信确认）。

仅依赖 Python 3.11 标准库（http.server + sqlite3），前端为原生 HTML/CSS/JS，无需构建。

## 启动

```bash
./run.sh                 # 首次自动播种演示数据并启动 http://127.0.0.1:8000
./run.sh --reseed        # 删除旧库，重建多经纪人冲突样例后启动
./run.sh --port 8123
```

也可分步：

```bash
python3 -m app.seed --force   # 播种（含并发冲突演示）
python3 -m app.server         # 启动
```

## 测试

```bash
python3 -m unittest discover -s tests -v
```

## 关键业务规则（种子中的签署版 v2026.09）

- **保护期**：客户就某房源「签到 + 短信确认」后，自次日起 30 个自然日为保护期；
  最后一天成交仍受保护，次日起为保护期外。未签到、未确认、已取消的带看不产生保护。
- **归属候选**：保护期内成交，首带经纪人 60%、末带经纪人 40%；首末同人 100%。
- **客户自行到店**：登记为 `WALKIN`，对应份额计入接待门店公盘，不计给个人。
- **同天多名经纪人带看**：并列展示全部候选及证据 → 状态「待裁决」，由主管裁量。
- **跨店协作**：外店经纪人带看他店房源须事先由**房源方门店主管**授权，否则拒绝并留痕；
  已授权带看的候选份额按 50/50 在「外店带看人 / 房源方门店公盘」间拆分。
- **裁决**：经纪人不能裁决自己作为候选的争议（利益回避）；只有主管可裁决；
  分成合计须 100%、须填理由；裁决时冻结规则版本全文与全部证据快照，永久留痕。

## 并发安全

`app/db.py` 的 `Database` 提供**线程局部连接**；写命令在 `BEGIN IMMEDIATE`
事务内完成「校验 + 追加事件 + 更新投影」，SQLite 写锁全局串行，
`ux_viewing_slot` 部分唯一索引是最后防线。并发登记同一
「房源 + 客户 + 时刻」时，恰有一条成功，另一条得到 409 冲突且**不产生双记录**；
取消带看会释放该槽位。

## 数据存放

- SQLite 事件库：`data/brokerage.db`（`events` 表为唯一事实来源，其余为可重建投影）
- 客户签字图：`data/signatures/*.png`（本地文件存储）
- 短信：`sms_outbox` 表 + 控制台回显的**模拟适配器**（`app/sms_adapter.py`），
  真实接入时实现同签名的 `send()` 即可

## 页面

- **房源检索**：突出地址、报价与带看时间线（每条带看含签到/签字/确认/保护期）
- **客户检索**：姓名/手机号检索、登记查重（精确 + 疑似）、个人带看与保护期
- **带看日历**：月视图，同日多人带看高亮；可登记、签到手写签名、客户输码确认、取消
- **佣金 / 争议**：金额与规则版本常驻；候选经纪人证据**并列卡片**展示；主管裁决与历史快照
- **审计与短信**：事件流、模拟短信发件箱、被拒绝动作（跨店/重复客户/利益回避）留痕

界面采用白、深灰与少量铜色，克制的内部工作台风格。

## 代码结构

```

app/sms_adapter.py  模拟短信
app/server.py       HTTP 路由与签字图落盘
app/seed.py         演示数据（多经纪人冲突等全部样例）
app/static/         前端
tests/test_domain.py 规则与并发测试
```
